# Telegram-бот «Свет дома» — версия 2.0

Один аккаунт Яндекса, несколько пользователей Telegram. Все разрешённые пользователи имеют одинаковые права на весь свет аккаунта. Бот работает в личных сообщениях.

## Версия 2.0: Telegram Mini App с тремя темами

**Для обновления на 2.0 используйте START_MINI_APP.md. Требуется обновить весь проект и настроить HTTPS-домен; инструкции ниже про замену только bot.py относятся к старым версиям 1.x.**

Появились избранные устройства на главном экране, крупные переключатели, выбор дома, комнаты, личные темы (светлая, тёмная, «Уютная дача»), добавление розеток в свет и настройки уведомлений. Панель запускается через кнопку бота. Права проверяются по подписи Telegram и белому списку. Текстовые функции сохранены.

## Обновление 1.3: полный отчёт и выбор розеток/выключателей

В диагностике появилась кнопка «📋 Скопировать всё»: она присылает один файл diagnostics_all.txt, включающий все устройства всех страниц. Перешлите файл для разбора или откройте его и выберите «Выделить всё → Скопировать». Telegram CopyTextButton ограничена 256 символами, поэтому большой отчёт отдаётся файлом. Токенов и заголовков авторизации в нём нет, но названия домов и устройств присутствуют. На экране диагностики указаны номер страницы и диапазон устройств.

В главном меню выбранного дома нажмите «➕ Добавить устройство в свет». Список содержит розетки и выключатели с функцией on_off. Выберите, например, «Розетка торшер», «Прожектор Андрея» или «Уличная гирлянда 1», затем нажмите «Добавить в свет». Это только добавляет устройство в меню, не включает его. После добавления оно доступно в свете своего дома всем пользователям белого списка, участвует в проверке доступности. Выбор сохраняется в SQLite после перезапуска. Через этот же экран можно убрать устройство из света без выключения питания. Настройки EXTRA_LIGHT_IDS продолжают действовать: устройства из переменной удаляются через настройки хостинга.

Для обновления остановите бот, замените только bot.py из архива, сохраните переменные и /app/data, затем запустите бот и отправьте /start. Новая таблица создаётся автоматически.

## Обновление 1.2: диагностика пустого списка света

Добавлены резервные способы определения дома по спискам devices в комнатах и группах. Если прямой связи с домом нет, а дополнительные связи противоречат друг другу, устройство остаётся в «Без привязки к дому»: бот не угадывает дом.

У каждого дома в списке отображается число распознанных светильников. В меню и при пустом списке есть «Диагностика», также доступна команда /diagnostics. Она показывает количество устройств, типы, названия, определённые дома и источник привязки. Выводятся только явно выбранные поля, без токенов, заголовков авторизации и полного ответа API. Отчёт содержит названия ваших домов и устройств; передавайте его только тому, кто помогает с настройкой. Страницы переключаются стрелками.

Если проблема повторяется, пришлите текст диагностики со страницами проблемных устройств. Это позволит определить причину на реальных данных. API-доступа к вашему аккаунту у разработчика нет, причина вашего случая пока не установлена. Выключатели и розетки не добавляются в свет автоматически: если ваше освещение представлено ими, их ID нужно указать в EXTRA_LIGHT_IDS.

Обновление: остановите бот, замените bot.py из архива, сохраните переменные и /app/data, перезапустите, отправьте /start → «Выбрать дом» → «Обновить».

## Обновление 1.1: выбор дома

При первом /start с несколькими домами бот предлагает выбрать дом. В главном меню есть «🏘 Выбрать дом». Свет, комнаты и избранное показываются только для выбранного дома. Выбор индивидуален для каждого Telegram ID и сохраняется после перезапуска.

Названия домов берутся из аккаунта Яндекса. В карточке лампы показан дом. Устройства без привязки к дому доступны в отдельном разделе «Без привязки к дому». Старые кнопки устройств другого дома не отправляют команды: сначала нужно переключить дом.

Уведомления продолжают работать по всем домам аккаунта и содержат название дома. Переключатель уведомлений пользователя действует на все дома. Выбор дома в меню не ограничивает права пользователя: каждый участник белого списка по-прежнему может выбрать любой дом.

Для обновления остановите бота, замените bot.py из этого архива, затем запустите бота и отправьте /start. Остальные рабочие файлы, переменные окружения и папку /app/data сохраните. Новая таблица для выбора дома создаётся автоматически, избранное и подписки остаются прежними.

## Возможности

- Выбор дома, список света и комнаты только выбранного дома; страницы по 10 записей.
- Включение / выключение. Яркость, температура белого, четыре RGB-цвета — по возможностям конкретного устройства. HSV и цветовые сцены в этой версии не реализованы.
- Личное избранное и личный переключатель уведомлений.
- Белый список Telegram ID, проверяемый при каждой команде и нажатии.
- Уведомления: устройство offline после двух успешных проверок подряд, восстановление online; сбой API и восстановление. Одно сообщение на изменение, без постоянного повторения.
- SQLite хранит подписки и избранное. Получатели уведомлений повторно сверяются с текущим белым списком.
- Таймауты, ограничение частоты запросов, обработка HTTP 429; повторяются только запросы чтения, команды автоматически не повторяются.
- Ответ команды проверяется по action_result конкретного устройства и умения. Отсутствие DONE не считается успехом.

## 1. Создать Telegram-бота

Откройте официального @BotFather в Telegram, отправьте /newbot и сохраните токен. Каждый пользователь должен открыть нового бота и нажать «Запустить».

Бот отвечает неразрешённому пользователю в личном чате его числовым Telegram ID, не раскрывая устройства. Запишите эти ID в ALLOWED_USER_IDS, разделяя запятыми. Пустой список не допускается. После изменения списка перезапустите бот. Права одинаковые у всех; управление списком — через настройки сервера.

## 2. Получить OAuth-токен Яндекса

Войдите в тот аккаунт, в котором находятся устройства приложения «Дом с Алисой».

1. Откройте https://oauth.yandex.ru/ и зарегистрируйте приложение.
2. Запросите права «Просмотр устройств умного дома» (iot:view) и «Управление устройствами умного дома» (iot:control).
3. Для получения токена вручную укажите Redirect URI https://oauth.yandex.ru/verification_code в параметрах платформы приложения.
4. Скопируйте Client ID и откройте в браузере:

   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID

5. Разрешите доступ. Из адреса/страницы результата возьмите access_token. В YANDEX_OAUTH_TOKEN вставьте только сам токен, без Bearer и без #access_token=.

Названия экранов кабинета могут меняться. Если приложение уже зарегистрировано, используйте его, проверив права. Client Secret для такого способа в бот не передаётся. По истечении или отзыве токена получите новый, замените переменную и перезапустите.

Не отправляйте токены в чаты, скриншоты или публичные репозитории.

Официальные инструкции:
- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol
- https://yandex.ru/dev/id/doc/ru/tokens/debug-token

## 3. Настройки

Можно задать переменные окружения на хостинге либо скопировать .env.example в .env рядом с bot.py и заполнить:

TELEGRAM_BOT_TOKEN=токен_от_BotFather
YANDEX_OAUTH_TOKEN=токен_Яндекса
ALLOWED_USER_IDS=123456789,987654321
POLL_SECONDS=120
DATA_DIR=data

Переменные окружения хостинга имеют приоритет над .env. После изменения нужен перезапуск.

POLL_SECONDS — пауза между завершением проверки всех ламп и началом следующей, минимум 60 секунд. По умолчанию 120. Каждая проверка делает один запрос списка и по одному запросу на устройство. Для большого количества света увеличьте интервал. Реальное время обнаружения потери связи обычно около 2–4 минут плюс длительность запросов; при ошибках API больше. Это периодический опрос, а не мгновенное push-уведомление.

## 4. Запуск на bothost.ru

Создайте/выберите Python-проект. Загрузите ZIP через функцию «Загрузка бота из архива» на Bothost либо распакуйте его для загрузки файлов. При подключении через Git загрузите его файлы в отдельный закрытый репозиторий и подключите этот репозиторий к проекту Bothost. Не добавляйте файл .env в Git. Файлы должны находиться в корне проекта: bot.py и core.py должны лежать рядом. Используйте Python 3.11 или 3.12, файл зависимостей requirements.txt, файл запуска bot.py. Названия элементов панели зависят от её текущего интерфейса.

Если панель предоставляет поле команды запуска, укажите:

python bot.py

Для установки зависимостей в терминале:

python -m pip install -r requirements.txt

Внесите переменные в настройки проекта, включите постоянную работу и автоперезапуск, если это предусмотрено тарифом. Боту нужен исходящий HTTPS к api.telegram.org и api.iot.yandex.net. Входящий порт, домен и webhook не нужны: используется long polling.

Для одного токена Telegram запускайте только один экземпляр. Не держите параллельно работающую локальную копию.

Для Bothost задайте DATA_DIR=/app/data: этот каталог предназначен для сохранения БД между обновлениями. В архиве также есть Dockerfile с этой настройкой. Сохраните папку data на постоянном диске хостинга. Не удаляйте её при обновлении. Иначе сбросятся подписки и избранное. Можно указать в DATA_DIR абсолютный путь к постоянному каталогу. Данные истории доступности хранятся в памяти: после перезапуска начинается новый цикл определения offline, уже недоступная лампа снова может вызвать одно уведомление.

## 5. Первая проверка

1. Откройте бота под разрешённым пользователем, отправьте /start.
2. Выберите дом → «Весь свет» → выберите лампу. В главном меню переключите дом через «Выбрать дом» и проверьте второй список.
3. Проверьте включение и выключение одной лампы, затем яркость и цвет, если кнопки есть. Яндекс может показывать состояние с задержкой: нажмите «Состояние» ещё раз.
4. Откройте бота под вторым разрешённым пользователем. Избранное и переключатель уведомлений у каждого свои.
5. Проверьте запрет доступа под пользователем вне списка.
6. Для проверки offline отключите питание одной лампы и дождитесь, пока Яндекс начнёт отдавать offline, затем двух проверок бота. Восстановите питание и проверьте сообщение online.

Уведомления включены по умолчанию после первого обращения разрешённого пользователя. Бот не может написать тому, кто его ещё не запустил. Уведомления о каждом включении света в эту версию не включены. Точное определение физического состояния зависит от данных производителя в API Яндекса.

## 6. Выключатели и розетки, управляющие светом

Автоматически показываются только типы devices.types.light и их подтипы. Реле/розетки не добавляются автоматически: среди них могут быть другие приборы.

Если ваш свет подключён к реле, узнайте ID этого устройства командой python list_devices.py (она только читает список из официального API GET /v1.0/user/info) и внесите ID в EXTRA_LIGHT_IDS, разделяя запятыми, затем перезапустите. Не используйте этот параметр для ворот и других механизмов. Токены при получении списка не публикуйте.

## 7. Ошибки

- HTTP 401/403: проверьте токен и оба права OAuth. Убедитесь, что выбран нужный аккаунт.
- HTTP 429: превышен лимит; бот делает паузу. Увеличьте POLL_SECONDS и избегайте частых нажатий.
- DEVICE_UNREACHABLE: команда не выполнена; проверьте лампу и приложение «Дом с Алисой».
- Конфликт Telegram polling: остановите второй экземпляр с тем же токеном.
- Нет уведомлений: пользователь должен запустить бот, оставаться в белом списке и включить уведомления; хостинг должен работать постоянно.
- После таймаута команды сначала проверьте состояние. Бот намеренно не повторяет отправку, если результат неизвестен.

Логи не содержат токенов и тел HTTP-запросов; HTTP debug-логирование не включайте. В логах есть Telegram ID, сокращённый идентификатор устройства, тип команды и request_id Яндекса для диагностики.
